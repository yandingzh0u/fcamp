2. 为什么这次不能继续让 Flow 全部工作在 q 坐标
-------------------------------------------------

此前方案定义：

    q = K_rho u
    u = K_rho^(-1) q
    action = b_rho + K_rho u

在没有 clamp 时，这条链严格化简为：

    action = b_rho + q

也就是说，如果 actor mean 本身直接输出任意 q，K_rho^(-1) 再 K_rho 会完全
抵消。rho 只改变 continuation base，却没有给 actor mean 带来真正的二阶控制
归纳偏置。这正是“看上去使用了 acceleration，实质上仍直接输出 action path”
的问题。

因此本计划唯一采用：

    actor mean、sample、rollout latent、logp、critic prefix 全部统一为 u；
    q 只作为 CPS 的物理探索几何和诊断坐标；
    实际执行必须调用一次且仅一次 u -> (v,a) 积分器。

因为 K_rho 是固定可逆矩阵，CPS 可以先在 q 中设计安全 covariance，再转换：

    Sigma_u = K_rho^(-1) Sigma_q K_rho^(-T)
    C_u     = frame_major_cholesky(Sigma_u)

rolling sampling 使用各 step 的 {L_u,s,xi_s}；最终 logp/KL 使用
C_u,F=chol(Sigma_u,F)。它们不要求字面上是同一个 factor，但必须精确诱导同一个
最终 marginal covariance：

    delta_final = sum_s w_s L_u,s xi_s
    Cov(delta_final) = Sigma_u,F = C_u,F C_u,F^T

不能直接把任意 K_rho^(-1)L_q 当作逐帧 conditional Cholesky，因为 z->q 的
逆变换不是天然 frame-major 下三角；只有对最终 Sigma_u,F 重新做固定 frame-major
Cholesky，逐帧 conditional density 的分解才成立。这只是同一 covariance 的
标准重因子化，不是事后修改/投影 covariance。


3. 必须先锁死的数学定义
-----------------------

3.1 唯一执行器

对每个环境和每个关节：

    v_i_raw = rho * v_(i-1) + u_i
    a_i     = clamp(a_(i-1) + v_i_raw, -5, 5)
    v_i     = a_i - a_(i-1)

最后一行不是可选修正。clamp 后必须把 v 投影回“真实执行 action 差分”，否则
下一 chunk 携带的是虚假的速度状态。

初始/reset 状态：

    a_prev = reset 后真实 env.last_action（当前环境契约下通常为0，但不硬编码）
    v_prev = 0

每个 chunk 结束：

    a_prev <- 最后一帧真实执行 action
    v_prev <- 最后一帧 action - 倒数第二个真实 action

若某环境在 chunk 中死亡，只更新它实际执行到的最后一帧；reset 后该环境的
(a_prev,v_prev) 单独清零，不得污染其他环境。

rho 固定为：

    rho = 2^(-1/4) = 0.840896415...
    rho^H = 0.5

因此在未触发 clamp 的线性区，u=0 时每经过一个完整 chunk，速度精确减半。

3.2 K_rho

无 clamp 时：

    a = b_rho(a_prev,v_prev) + K_rho u

其中：

    b_i = a_prev + sum_(t=0..i) rho^(t+1) * v_prev
    K_rho[i,j] = (1-rho^(i-j+1))/(1-rho),  j<=i
    K_rho[i,j] = 0,                         j>i

K_rho 和 K_rho^(-1) 只允许有一个 canonical implementation；训练、validation、
deployment、测试都调用它，禁止各文件重新抄一份公式。

3.3 真正的跨 chunk carry 注入（unclamped linear invariant）

令 exploration 造成的 action-path 偏移为：

    epsilon_q = K_rho epsilon_u

末端速度注入：

    delta_v_T = (D epsilon_q)_T

永久 action-level carry 注入：

    delta_c = epsilon_q,T + alpha * (D epsilon_q)_T
    alpha   = rho/(1-rho) = 5.285213...

只让 dT 看起来小，不能保证 delta_c 小。所有 CPS 可行性检查必须直接计算
delta_c；delta_ratio<1 也绝不能单独作为“正常”的证据。

3.4 CPS 的直接可行坐标

每个关节使用同一个 4-D temporal 坐标变换，不在 116-D 退化特征空间里挑方向：

    z0 = q0                         # 首帧注入
    z1 = q1 - q0                    # chunk 内 bridge 增量
    z2 = q3 - q2                    # terminal velocity 注入
    z3 = q3 + alpha*(q3-q2)         # persistent carry 注入

该变换可逆：

    q0 = z0
    q1 = z0 + z1
    q3 = z3 - alpha*z2
    q2 = z3 - (alpha+1)*z2

固定 CPS factor 的构造原则：

    1. 先在 4-D z 坐标求一个位于可行域内部、有明显 margin 的固定 factor；
    2. 同一 temporal factor 成组复制到全部 29 个关节；
    3. 每个 flow step 解析得到 Sigma_q,s，再转成 Sigma_u,s=K^-1 Sigma_q,s K^-T；
    4. sampling 可使用任意满足 L_u,s L_u,s^T=Sigma_u,s 的精确 factor；
    5. rolling 最终 covariance 必须由 4 个 flow step 的真实系数解析合成；
    6. PPO density 对最终 Sigma_u,F 做 frame-major Cholesky 得到唯一 H_u,F；
    7. sampling、logp、KL、诊断必须对应同一最终 marginal covariance；
    8. 不允许采样后再修 covariance 或 action path。

为使最终 policy density 真正唯一，随机递推必须严格保持仿射：

    m_(s+1)     = FlowMean_s(obs, m_s)              # 网络只看 deterministic mean
    delta_(s+1) = p_s*delta_s + n_s*L_u,s*xi_s     # xi_s 独立标准高斯
    u_final     = m_final + delta_final

禁止把 sampled u 喂回 nonlinear velocity network，否则最终分布不再是 Gaussian，
解析 rolling covariance 和解析 KL 同时失效。定义：

    w_s       = n_s * product_(k>s) p_k
    Sigma_u,F = sum_s w_s^2 * L_u,s L_u,s^T
    Sigma_q,F = Kbar_rho Sigma_u,F Kbar_rho^T
    Kbar_rho  = K_rho tensor_product I_A

若四个 flow step 共享同一基础 factor，必须按 sum_s(w_s^2) 归一化 step factor，
保证文档设计的尺度就是 final marginal 的尺度。

PPO old/new logp 只定义在最终：

    u_final ~ N(m_final, Sigma_u,F)

rollout old_logp 形状为 [batch,H]，中间 flow path 只用于采样过程/诊断，不参与
PPO density。H_u,F=chol(Sigma_u,F) 按 frame-major 顺序分解 final joint density；
不能再把四个辅助 flow transition 的 logp 累加成另一套 policy density。

初始固定 factor 不再追求旧 q_RMS=0.733。先以约 0.20 的 final q RMS 作为
物理尺度起点，但它不是必须强塞满的 trace equality；联合硬约束决定实际可行
能量，宁可降低 exploration，也不能把多余能量藏到低秩/少数关节/末帧。

固定及可学习 factor 的硬门槛全部作用于“4 个 flow step rolling 完毕后的最终
Sigma_q”，不是单步 innovation：

    max_joint RMS(q0)          <= 0.20
    max_joint RMS(Dq_T)        <= 0.032（nominal fixed factor <=0.028）
    max_joint RMS(q_T)         <= 0.15
    max_joint RMS(delta_c)     <= 0.02
    max_joint RMS(Dq)          <= 0.30
    max_joint_RMS/median_RMS   <= 1.25（q全帧及每个z坐标分别检查）

注意 q_T=delta_c-alpha*Dq_T，所以 dT、qT、carry 不是三个可以独立吃满的预算。
由联合门槛可得 dT<=0.03217；固定 factor 的 nominal dT 必须<=约0.028，不能按
0.04 初始化后期待相关性碰巧补救。

raw Sigma_q 只检查上述物理 RMS，不施加 condition/effective-rank 门槛，否则
q_RMS≈0.20、carry<=0.02 与 raw condition<=1e3 在数学上不相容。谱门槛定义在
按各 z 物理预算标准化后的 covariance/correlation：

    Rbar        = R tensor_product I_A              # frame-major flatten
    Sigma_z     = Rbar Sigma_q,F Rbar^T
    Sigma_z,std = S_z^(-1) Sigma_z S_z^(-T)
    S_z         = diag(0.20,0.30,0.032,0.02) tensor_product I_29
    effective_rank = trace(Sigma_z,std)^2 / trace(Sigma_z,std^2) >= 58
    lambda_max(Sigma_z,std)/trace(Sigma_z,std) <= 0.05
    condition_number(Sigma_z,std) <= 1.0e3

S_z 的顺序严格对应 (z0,z1,z2,z3)=(q0,q1-q0,dT,carry)，使用 hard cap
0.032，而不是 fixed factor 的 nominal 0.028；这样不同 run 的标准化谱可复现。
qT<=0.15 和完整 Dq<=0.30 仍在 raw physical covariance 上另行检查。

第3.4节的全部raw physical与standardized-z约束自动继承到u5 smoke、每个
validation里程碑、统一早停和最终验收；后文即使为简洁只重复其中几项，也不
代表其余约束可以省略。

delta_c 保留很小的非零方差，是为了保持完整密度和有限 KL。不能宣称它数学上
完全为零。它的有限运动时域累积必须满足解析上界：完整动作约 324 帧，即约
81 个 chunk，独立 carry 的标准差上界约为 sqrt(81)*0.02=0.18。Monte Carlo
必须与这个上界一致且不能出现超线性增长。

3.5 可学习 CPS 只能围绕固定安全 factor 学习

最终可学习结构采用直接 factor，不采用投影器：

    temporal correlation: 4x4 full-rank correlation
    joint correlation:    29x29 full-rank correlation
    joint marginal:       显式保持平衡
    coordinate scales:    在固定安全 factor 周围的有界范围内变化

可使用 identity-blended correlation 保证谱下界：

    C_safe = (1-lambda)*I + lambda*C_raw_correlation
    0 <= lambda <= lambda_max < 1

每个 tentative CPS optimizer step 后，直接检查实际 rolling factor。若违反任何
硬门槛，完整 rollback CPS 参数和 optimizer state；禁止把非法 factor 再投影成
另一个 factor。CPS 使用独立 optimizer、独立 LR=3e-5、独立 grad clip。

3.6 PPO trust region

每次 rollout 固定一份 behavior actor + behavior CPS factor。整个 update 的锚点
始终是该 behavior snapshot，不得在每个 minibatch 重新定义锚点。

actor 和 CPS 必须是两个独立事务，不能共享 backward graph：

    actor transaction：冻结 CPS，重新 forward/backward，只 tentative 更新 actor；
    CPS transaction：冻结已接受的 actor，重新 forward/backward，只 tentative 更新 CPS。

每个事务：

    1. 保存对应参数、全部 Adam state、param-group LR、scheduler/controller/retry 状态；
    2. tentative optimizer step；
    3. 对最终 latent-u Gaussian 计算解析 old->new prefix joint KL；
    4. frame i KL = KL(u_0:i)-KL(u_0:i-1)，得到 exact conditional contribution；
    5. 对该 frame 的有效 behavior observations 按固定 stream 权重求经验均值；
    6. 要求 max_i E_rollout[KL_i] <=4*desired_kl=0.04；
    7. 超限则完整 rollback，LR/2，最多重试 3 次；
    8. 三次仍失败则跳过该事务；actor normalizer仍保持behavior snapshot状态。

“exact”只指给定 stored behavior conditioning 后的 final latent-u 解析 Gaussian
KL；它不是 clamp 后 executed-action marginal density 的 exact KL。对 rollout
状态分布的期望是固定 behavior probe 上的经验均值，不是对单个 sample 取最大。
behavior snapshot 必须包含 actor normalizer snapshot、u_final sample、behavior
mean/covariance（或不可变behavior actor）、continuation state和有效mask；中间
flow path不进入PPO契约。actor normalizer在minibatch事务期间冻结。

policy transaction 的提交顺序写死为：

    1. update开始保存actor、CPS、两套optimizer、LR/controller和actor normalizer；
    2. 完成tentative actor/CPS事务，但不更新critic/disc/prefix normalizer；
    3. 用rollout raw obs在actor-normalizer副本中计算candidate moments，不先提交；
    4. 用candidate actor+candidate CPS+candidate normalizer对完整rollout分块审计；
    5. 通过才原子提交actor/CPS/actor normalizer；
    6. 之后才允许critic、disc、prefix normalizer和相应optimizer消费该rollout。

若完整审计 max_frame_KL>0.04，恢复 policy-transaction 起点的 actor/CPS/optimizer/
actor-normalizer；保留“LR减半”的安全controller结果，然后跳过本轮policy更新。
因为critic/disc/prefix normalizer尚未更新，不需要伪装成能恢复整个训练世界。
collection已经产生的sampler/replay状态属于behavior rollout，不纳入policy事务。
禁止保存或继续使用越界的actor/CPS/normalizer组合。

policy LR 永远不得超过配置 base LR=3e-4。CPS covariance 开放学习后，KL 必须
包含 mean、trace、logdet 全项，不能继续用 0.5*sample_log_ratio^2 冒充 exact KL。


4. 全局实验纪律
-----------------

正式性能实验统一：

    environment.num_envs = 8192
    rollout_env_steps     = 24
    policy_epochs         = 5
    num_mini_batches      = 4
    seed                  = 0（开发阶段）
    validation_fixed_seed= 0
    validation_every      = 25（至少到 u100；之后仍建议保持 25）
    H                     = 4
    flow_steps            = 4

原因：f94 历史基线使用 8192 env。每 update 为 196,608 formal transitions，保持
8192 才能同时对齐 transitions/update 和 optimizer-step density。日志的累计
transition 还包含一次 discarded discriminator warmup，因此历史累计值为：

    cumulative transitions = (update+1)*8192*24

例如 u50 为 10.027M，而不是 9.830M。4096-env 的旧 metric/phys run 只能按
transition 映射作为故障证据，不能直接按相同 update 与 f94 比性能。

允许 4096 env 的唯一场景是 u5 工程 smoke；它不能用于性能放行。

任何涉及 latent 语义、context 维度、CPS factor 或 optimizer contract 的跨阶段切换：

    不从旧阶段的 checkpoint resume；
    不复用旧 replay/normalizer/optimizer；
    都从相同 seed 的 fresh initialization 开始。

同一 schema、同一语义、同一 schedule 的意外中断允许普通 resume，但训练器会
重新 reset simulator，并以 a_prev=reset后真实env.last_action、v_prev=0开始新轨迹；它
不是原轨迹的 bit-exact continuation。若未来要求 bit-exact 续跑，必须同时保存
simulator state 和前一帧 action，不能只靠 env.last_action 猜 v_prev。

唯一例外是第 11 步规定的固定/可学习 CPS controlled fork，因为两边从完全相同
的 schema 13、u-space policy 和固定 factor checkpoint 分叉，且目的就是隔离
“开放 covariance 学习”这一变量。

每次运行必须保留：resolved_config.json、source_snapshot.tar.gz、git_status.txt、
metrics.jsonl、train.log 和所有 gate checkpoint。运行中禁止边跑边改代码。

trajectory；不足8192条则该次评估无效并原配置重跑。对同一个training seed，把5个
validation seed的40960条逐trajectory记录直接拼接，再从拼接
样本计算一个 pooled mean、p50、p95 和 motion completion，不能先算5个摘要再平均，
也不能挑最好的一次。boundary、安全、saturation、carry和KL不取平均：对5次评估、
全部joint/frame取最坏值（上界型指标取max，下界型谱指标取min），这个worst case
必须通过第3.4节和步骤12的全部安全门槛。训练期max_frame_KL使用该training seed
到u500所有accepted update的历史最大值，解析covariance门槛使用u500 checkpoint的
精确值，不用有限样本估计替代。

最终放行条件：

    对三个training seed的pooled mean/p50/p95/completion分别取跨seed中位数；
    这4个中位数逐项满足步骤12 u500性能门槛；
    三个training seed中的每一个（不是“至少一个”）都满足步骤12的u300性能底线；
    每个training seed的5-validation-seed worst-case boundary、安全、carry、KL
    门槛全部通过；
    不能只报告最好的 seed 或最好的 validation seed。


7. 统一早停规则
---------------

以下任一发生，立即终止当前 run，不 resume 该 checkpoint：

    nonfinite_count > 0
    accepted step 的 max_frame_KL > 0.04
    actor LR > 3e-4
    CPS 参数应学习却没有 grad/Adam state/parameter delta
    per-joint q0/qT/dT/carry/Dq 任一硬帽被实际 factor 突破
    standardized-z effective rank <58 或 standardized-z top eigen/trace>0.05
    saturation raw fraction >=0.0150（即1.5%）
    saturation 连续20 updates上升且已超过0.0100（即1%）
    单次 validation steps_mean 相对最近 best 下降>15%（无条件立即停）
    或相对最近best累计下降>10%，且steps_p50、phase0 p50、ep_len均无实质进展
    连续小幅波动不早停；f94曾323.50->322.87->319.97->323.66后恢复
    sampler top_prob>0.45 且 phase0 p50 连续两次不进步

clip fraction 0.10~0.30 只作为健康观察区，不单独决定停训。delta_ratio 小于1也
不自动代表正常：必须同时看绝对 delta、d2、state boundary、steps、saturation。
completion 历史上高度非单调，也不能单独用于趋势早停。本文 delta<=1.15、
d2<=1.25、state ratio<=1.15 和 saturation 线均是刻意的设计安全 gate；其中
d2=1.25 包住旧metric u300的1.2025。f94本身没有记录saturation，不能伪称其为
f94高性能实证。

9. 最后一句判断标准
-------------------

这次不是“给 qT 加一个 cap”，也不是“把 physical projector 的 eigenvalue 再调一
调”。真正的根改是同时替换四个基本契约：

    旧 residual action actor -> 真正 u-space acceleration actor
    无 velocity 的 chunk restart -> 真实 (a,v) continuation
    事后修 covariance -> 直接生成可行的 carry-controlled sampling factor
    局部近似 KL -> 固定 behavior 锚点的 exact trust region

只有固定 factor 版本先通过 u50/u100/u150/u200，才允许学习 covariance；只有最终
同时达到 f94 生存性能和新的边界绝对门槛，才叫根本解决。
